  beat 2 [21.2]   15.95 -  26.03   [[Post-hoc: a method explains a {f:trained model} on one {x:input}]] Start with post-hoc. The model f is already trained. An explanation method takes the model and one input, and returns some evidence about the prediction.
  beat 3 [21.3]   26.75 -  39.70   [[Saliency in a tiny example: one {x:image}, three {y:classes}]] One family asks which pixels mattered. Start with a tiny example: a three by three image of a vertical bar, and a model that scores three classes: vertical bar, horizontal bar and dot.
  beat 4 [21.4]   40.23 -  54.90   [[Each {y:class score} is a weighted sum of the nine {x:pixels}]] Each class has its own nine weights, and its score is the weighted sum of the pixels.   beat 9 [21.9]  123.06 - 133.87   [[Occlusion: grey out a {x:patch} and measure how far the {y:score} drops]] A second family changes the input. Grey out one patch, run the model again, and measure how much the score drops. That is the occlusion map we computed for the gull in Part 1.

## s24  Grounding the concepts  (duration 212.40 s)
  beat 1 [24.1]    0.40 -   7.31   [[Nothing checks that a {c:concept} is really in the {x:image}]] Label-free models and LaBo share a weakness: nothing checks that a concept is actually visible in the image.
  beat 2 [24.2]    8.03 -  19.09   [[Naming a {c:concept} is not the same as pointing at it]] The fix rests on a simple intuition. Naming a concept is not the same as pointing at it. So ask a detector to point at each concept in the image, and count only the concepts it can find.
  beat 3 [24.3]   19.99 -  33.99   [[Three ways a {c:concept} can fail]] There are three ways a concept can fail. Some are not visual, such as a gull's call. Some describe the setting, not the bird.
