## s09 | Concept leakage | 0.4 | 0.8
[[What does a {c:concept value} carry?]] Each concept value is a single number on its way to the task head. What exactly does that number carry? || 0.8
[[Leakage: the {c:value} carries more, and the {f:head} uses it]] A concept value should answer one question: is this concept present? Leakage is when the value carries more than that answer, and the task head uses the extra. || 1.0
[[Two zebras with the same {c:binary label}]] Here is a constructed example. A plains zebra and a Grévy's zebra both have stripes, so both get the label stripes equals 1. || 0.8
[[Different {c:scores}, and the {f:head} cuts between them]] A soft predictor scores plains zebras around 0.72, and Grévy's zebras, with narrower and denser stripes, around 0.96. Both mean stripes present, yet a threshold near 0.84 separates them almost perfectly. The binary label alone leaves the head at chance. || 1.0
[[The {c:stripes value} also carries {k:stripe density}]] So the stripes value also carries stripe density, which nobody named and nobody can inspect. That hidden part is the leakage. || 1.0
[[A correct {e:edit} gives the wrong {y:species}]] Now correct a plains zebra's stripes value to 1, its true value. The head reads anything above 0.84 as Grévy's zebra, so the correct edit gives the wrong species. || 1.0
[[{k:Implicit} leakage hides in the {c:score}; {k:explicit} takes a side path]] That was implicit leakage, inside a continuous score. Explicit leakage is a side path that carries latent features around the concepts, so an edit no longer controls everything the head sees. Ordinary variation in confidence is not leakage. Leakage is systematic, and the head uses it. || 1.0
